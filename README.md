## Alem — задачи бизнеса и студенческие команды

Интерактивный MVP на Vite и JavaScript: чёрный текст, плоские фоны и синие акценты. Без регистрации.

### Запуск

Node.js 20.19+ и npm:

```bash
npm ci
npm run dev
```

Открыть http://localhost:5173. Dev-сервер слушает IPv4 и IPv6; порт закреплён через `--strictPort`, поэтому при занятом 5173 запуск сообщит об ошибке, а не незаметно выберет другой адрес.

```bash
npm test
npm run build
npm run preview
```

### Сценарий демонстрации

1. Переключиться на «Бизнес» слева. На телефоне переключатель в верхней панели.
2. Создать задачу: название и короткое описание проблемы, например «Теряем заявки в мессенджерах».
3. Ответить на вопросы помощника по одному. Можно вернуться к предыдущему ответу или пропустить вопрос. Затем перейти к карточке.
4. Проверить карточку: раскрыть нужный раздел, чтобы изменить сведения. Справа виден предварительный рейтинг; подсказка открывает нужное поле.
5. Подтвердить сведения и опубликовать. Даже задача с низким рейтингом доступна в каталоге.
6. Переключиться на «Команда», найти задачу и отправить идею, план, срок и HTTP(S)-ссылку на прототип.
7. Вернуться в «Бизнес» → «Отклики команд». Выбрать или отклонить предложение вручную. Можно выбрать несколько команд; остальные отклики остаются доступны.
8. Со стороны выбранной команды отправить результат этапа. Подтвердить его со стороны бизнеса: команда получает 10 баллов, повторное начисление невозможно.

Для быстрого просмотра есть пять опубликованных задач, черновик, пять предложений и пять внешних профилей команд. У Orbit подготовлен результат этапа для проверки. Все организации, контакты и предложения демонстрационные.

### Возможности

**Бизнес:** свои задачи и черновики; конструктор из трёх шагов; уточняющие вопросы; редактируемая карточка; рейтинг с расшифровкой; публикация и удаление; фильтры входящих предложений; профили команд; ручной выбор/отклонение; подтверждение результата; профиль компании.

**Команда:** общая лента, поиск, фильтры по теме и готовности; детали задачи; закладки; предложения со статусом решения бизнеса; сдача этапа; профиль и баллы.

Черновики и состояние конструктора сохраняются в браузере. Редактирование опубликованной задачи не меняет карточку в каталоге до подтверждения. Любое изменение формы сбрасывает флажок подтверждения. Опубликованные задачи сортируются по рейтингу; низкая готовность не ограничивает отклики. Созданные пользователем значения экранируются перед отображением.

Кнопка корзины удаляет собственный черновик или задачу после подтверждения. Удалённая задача исчезает из каталога, закладок и активного кабинета бизнеса; новые отклики и сдача этапа недоступны. История предложений и баллы за уже подтверждённые этапы сохраняются. Можно удалить и текущий несохранённый черновик.

### Русский и казахский языки

Переключатель **RU / ҚАЗ** в верхней панели переводит интерфейс, формы, статусы и подсказки. Выбор сохраняется после обновления страницы. Переключение не сбрасывает введённые ответы и несохранённые поля профиля. Тексты пользователей и демонстрационных задач остаются на исходном языке.

Новые вопросы AI и пояснения рейтинга создаются на выбранном языке. Карточка и цитаты сохраняют исходные факты без перевода. Уже полученные ответы AI автоматически не перегенерируются: для них есть кнопки обновления вопросов и повторной оценки. Переключение языка само по себе не вызывает платный API-запрос и не меняет рейтинг.

### Рейтинг

Рейтинг оценивает конкретность сведений, а не факт заполнения поля. При сборке карточки GPT-5 mini проверяет каждое поле: 0 — нет ответа, 1 — общее направление, 2 — полезные сведения с существенными пробелами, 3 — почти готово, 4 — достаточно для работы. Для каждого решения возвращаются краткая причина и дословные цитаты из соответствующего поля. Сервер проверяет схему и цитаты, а итог считает сам.

Веса групп: контекст + потребность — 20; данные — 20; ожидаемый результат — 15; критерии успеха — 15; ограничения — 10; пользователи — 10; контакт + формат связи — 10. Уровень группы равен среднему уровню её полей: хороший ответ учитывается, даже когда соседнее поле пустое. Баллы группы = `вес × средний уровень / 4`; итоговая сумма округляется до целого от 0 до 100. Модель проверяет и противоречия, например доступность обезличенных данных при требовании работать только с ними.

«Еще в процессе», «Не-а», повтор одного ответа в нескольких полях и демонстрационный контакт не приносят баллов даже при ошибочной высокой оценке модели. Общие фразы вроде «главное успеть» оцениваются по смыслу: срок не заменяет проверяемые критерии приёмки. Полные баллы требуют выполнения всех критериев. Семантическая оценка модели всё равно может ошибаться и не подтверждает реальное существование материалов или контакта.

В блоке «Что уточнить» видны причины и переходы к нужным полям. Оценка привязана к точному тексту карточки: после правок она недействительна. Когда бизнес подтверждает карточку и нажимает «Опубликовать» или «Сохранить изменения», система автоматически проверяет изменённый текст и пересчитывает рейтинг. Можно запустить проверку заранее кнопкой «Оценить с AI»; при актуальной оценке публикация не делает повторный запрос. Изменённые поля не переписываются при повторной проверке. Подтверждение человеком само по себе баллов не добавляет.

Если AI недоступен или его ответ не прошёл проверку, показывается «Готовность не оценена», а не оценка по заполнению. Такую задачу можно опубликовать, найти и выбрать; для сортировки она получает 0. Оценки, полученные по заполнению полей или устаревшей версии рубрики, сбрасываются при загрузке без удаления карточек, черновиков и откликов. Демонстрационные задачи без новой проверки тоже показываются без рейтинга.

### Подключение AI

1. Скопировать `.env.example` в `.env` (не перезаписывать существующий ключ).
2. Заполнить `OPENAI_API_KEY` ключом проекта OpenAI. По умолчанию используется `OPENAI_MODEL=gpt-5-mini`.
3. Перезапустить `npm run dev`, если сервер уже работал. Для собранного приложения использовать `npm run preview`.

`.env` исключён из Git. Ключ читается только сервером; префикс `VITE_` для него не используется.

Конструктор делает два запроса: при нажатии «Уточнить с AI» — `POST /api/ai/questions`; после последнего вопроса — `POST /api/ai/card` (сборка + оценка содержания в одном вызове модели). Кнопка повторной проверки вызывает `POST /api/ai/review`. Та же ручка автоматически вызывается при подтверждённой публикации, если актуальной оценки нет. Это дополнительный платный вызов. Отмена или уход со страницы во время проверки не публикуют правки; повторное нажатие не создаёт параллельных запросов. При сбое AI подтверждённая карточка публикуется без рейтинга с сообщением о причине; старая оценка изменённого текста не используется. Сервер вызывает OpenAI Responses API со строгой JSON-схемой и `store: false`. Ввод и правки сами по себе не вызывают модель. Реальные запросы оплачиваются по API-тарифу проекта.

Первый этап возвращает 3–6 вопросов по конкретному описанию. Второй распределяет дословные фрагменты исходного текста по полям; заполненные пользователем поля сохраняются. Каждый фрагмент для пустого поля проверяется на присутствие в исходных строках; разница в пробелах и переносах допустима, изменение фактов — нет. Для заполненных полей модель возвращает пустые массивы, а сервер сохраняет оригинал: это сокращает ответ и исключает ошибки повторного цитирования. Это извлечение и структурирование, а не свободное сочинение: отсутствующие сведения остаются пустыми. Семантическую правильность распределения проверяет бизнес перед публикацией.

В интерфейсе есть ожидание, отмена, сохранение ответов, предпросмотр карточки и ручное подтверждение. Неподтверждённый текст не публикуется автоматически. Если повторная оценка не удалась, уже полученная оценка той же версии остаётся видна с пояснением; после изменения текста старая оценка по-прежнему недействительна.

Без ключа, при ошибке провайдера, таймауте, некорректном JSON или неподтверждённых исходным текстом фрагментах включается явно обозначенный локальный режим. Он сохраняет введённые сведения и задаёт 3–6 вопросов по правилам, но не выдаёт семантическую оценку. Общий бюджет серверного запроса — 60 секунд; клиент ждёт до 65 секунд. После ошибки структуры или цитат сервер делает максимум одну дополнительную попытку в пределах того же бюджета (это дополнительный платный вызов). При этом уже проверенная карточка сохраняется, повторно запрашивается только её оценка. Сетевая ошибка, отказ, лимит и незавершённый ответ имеют отдельные причины; автоматического бесконечного повтора нет. Ограничение — 12 запросов в минуту с одного IP. Отмена в интерфейсе не гарантирует отмену уже начатого платного запроса у провайдера.

Серверный адаптер встроен в Vite для локальной демонстрации и `preview`; простая раздача `dist` без этого сервера работает только с локальным помощником. Это не публичный сервер для размещения открытого API-ключа без контроля доступа.

Промпты: `server/ai.js`. Схемы: `src/ai-contract.js`. Вход ограничен полями задачи: профили участников и предложения команд модели не передаются. Промпт запрещает использовать личные и чувствительные признаки участников, выбирать команды и назначать исполнителей. Рабочий контакт оценивается по наличию канала связи. Рекомендации по интересам и навыкам пока не реализованы; весь каталог доступен командам независимо от рейтинга.

Вход всех трёх ручек: `{locale: "ru" | "kk", task: {title, description, context, users, data, result, success, constraints, contact, interaction, category, weeks}}`. Без `locale` используется русский язык.

Выход вопросов: `{mode, questions: [{key, question}], notice?}`. Выход карточки: `{mode, card: {...fields}, assessment, score, notice?}`. Повторная проверка возвращает `{mode, assessment, score, notice?}`. `assessment` содержит версию рубрики, снимок текста и оценки полей; при недоступности проверки `assessment` и `score` равны `null`. Если карточка успешно извлечена, но оценка недоступна даже после повтора, ответ сохраняет `mode: openai`, карточку и `assessmentStatus: unavailable` с причиной. `mode` равен `openai` или `local`.

Во всех ответах также возвращается `locale`; оценка сохраняет свой `assessment.locale` для языка пояснений.

### Архитектура и интеграция

- `src/main.js` — общий интерфейс, переключение ролей и события.
- `src/business.js` — кабинет бизнеса, конструктор и решения по откликам.
- `src/student.js` — каталог, профиль, предложения и сдача результата.
- `src/store.js` — общие данные, демонстрационные профили и отклики, переходы состояний.
- `src/scoring.js` — формула рейтинга, проверка оснований оценки и актуальности версии карточки.
- `src/assistant.js` — проверка вопросов и локальный режим.
- `src/ai-client.js` — запросы, отмена и резервный режим.
- `src/ai-contract.js` — схемы, очистка входа, проверка источников карточки.
- `server/ai.js`, `vite.config.js` — серверные ручки и вызов OpenAI; ключ остаётся на сервере.
- `src/ui.js`, `src/icons.js` — общие функции интерфейса.
- `src/i18n.js`, `src/locales/kk.js` — переключение языка и казахские переводы.
- `src/style.css`, `src/business.css` — стили обеих сторон.
- `tests/*.test.js` — рейтинг, переходы, удаление и сохранение баллов, проверка AI-ответов, выдуманные факты, отсутствие ключа, ошибки API, локализация и HTTP-проверки. Тесты используют подставные ответы, платные API-запросы не выполняются.

Хранение: `alem.workspace.v2` (задачи, команды, предложения, закладки и бизнес), `alem.editor.v2` (текущая форма), `alem.role` и `alem.locale` в localStorage. Старые профиль, закладки и предложения из первой версии импортируются при создании нового хранилища.

Основные модели:

- Task: `id`, `ownerId`, `title`, `description`, `context`, `users`, `data`, `result`, `success`, `constraints`, `contact`, `interaction`, `category`, `weeks`, `published`, `confirmed`, `score`, `assessment`, `deletedAt?`.
- Proposal: `id`, `taskId`, `teamId`, `idea`, `plan`, `deadline`, `link`, `status` (`pending`, `selected`, `rejected`), `createdAt`.
- Milestone внутри Proposal: `description`, `link`, `status` (`submitted`, `confirmed`), даты отправки/подтверждения.

Сервер подключён для AI. Общей базы данных и синхронизации между браузерами пока нет; регистрация не предусмотрена. Переключение ролей — только демонстрационная функция. Для интеграции заменить операции хранилища API-вызовами; на сервере проверять владельца задачи, выбранную команду, переходы статусов и однократность подтверждения этапа. Рейтинг также должен пересчитываться сервером. В демо доступен один этап на предложение. Картинки и иконки не требуют внешних API; шрифт загружается с Google Fonts с системным запасным вариантом.
