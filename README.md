## Alem — задачи бизнеса и студенческие команды

Монохромный интерактивный MVP на Vite и JavaScript. Ветка: `feat/business-ui`.

### Запуск

Node.js 20.19+ и npm:

```bash
npm ci
npm run dev
```

Открыть http://localhost:5173 (точный адрес — в терминале).

```bash
npm test
npm run build
npm run preview
```

### Сценарий демонстрации

1. Переключиться на «Бизнес» слева. На телефоне переключатель в верхней панели.
2. Создать задачу: название и короткое описание проблемы, например «Теряем заявки в мессенджерах».
3. Ответить на вопросы помощника по одному. Можно вернуться к предыдущему ответу или пропустить вопрос. Затем перейти к карточке.
4. Проверить карточку: раскрыть нужный раздел, чтобы изменить сведения. Справа виден предварительный рейтинг; подсказка открывает нужное поле.
5. Подтвердить сведения и опубликовать. Даже задача с низким рейтингом доступна в каталоге.
6. Переключиться на «Команда», найти задачу и отправить идею, план, срок и HTTP(S)-ссылку на прототип.
7. Вернуться в «Бизнес» → «Отклики команд». Выбрать или отклонить предложение вручную. Можно выбрать несколько команд; остальные отклики остаются доступны.
8. Со стороны выбранной команды отправить результат этапа. Подтвердить его со стороны бизнеса: команда получает 10 баллов, повторное начисление невозможно.

Для быстрого просмотра есть пять опубликованных задач, черновик, пять предложений и пять внешних профилей команд. У Orbit подготовлен результат этапа для проверки. Все организации, контакты и предложения демонстрационные.

### Возможности

**Бизнес:** свои задачи и черновики; конструктор из трёх шагов; уточняющие вопросы; редактируемая карточка; рейтинг с расшифровкой; публикация; фильтры входящих предложений; профили команд; ручной выбор/отклонение; подтверждение результата; профиль компании.

**Команда:** общая лента, поиск, фильтры по теме и готовности; детали задачи; закладки; предложения со статусом решения бизнеса; сдача этапа; профиль и баллы.

Черновики и состояние конструктора сохраняются в браузере. Редактирование опубликованной задачи не меняет карточку в каталоге до подтверждения. Любое изменение формы сбрасывает флажок подтверждения. Опубликованные задачи сортируются по рейтингу; низкая готовность не ограничивает отклики. Созданные пользователем значения экранируются перед отображением.

### Рейтинг

За группу начисляется полный вес, когда все её поля содержат сведения: контекст + потребность — 20; данные — 20; ожидаемый результат — 15; критерии успеха — 15; ограничения — 10; пользователи — 10; контакт + формат связи — 10.

Пустые значения и заглушки «Уточняется», «Не знаю», «Пока не предоставлены» не засчитываются. До подтверждения показывается только предварительная оценка. Подтверждённая оценка пересчитывается при публикации изменений, включая уменьшение при удалении сведений. Уровни: 0–39, 40–69, 70–89, 90–100. Это прозрачная проверка полноты, а не семантическая оценка качества текста.

### Помощник

Внешняя модель пока не подключена. `src/assistant.js` содержит явно обозначенную локальную заглушку: она выбирает вопросы по отсутствующим полям и учитывает контекст заявок или продаж. Ответы переносятся в карточку без добавления фактов.

В файле есть `SYSTEM_PROMPT`, контракт и валидатор ответа. Вход: `{description: string, fields: object}`. Выход: `{questions: [{key: string, question: string}]}` — от 3 до 9 вопросов по разрешённым ключам. Некорректный JSON, повторяющиеся/неизвестные ключи или неполный ответ переключают обработку на локальные вопросы. Для настоящего AI нужен серверный адаптер; ключ API не должен попадать во фронтенд.

### Архитектура и интеграция

- `src/main.js` — общий интерфейс, переключение ролей и события.
- `src/business.js` — кабинет бизнеса, конструктор и решения по откликам.
- `src/student.js` — каталог, профиль, предложения и сдача результата.
- `src/store.js` — общие данные, демонстрационные профили и отклики, переходы состояний.
- `src/scoring.js` — чистая формула рейтинга и проверка заполнения.
- `src/assistant.js` — контракт помощника и локальный режим.
- `src/ui.js`, `src/icons.js` — общие функции интерфейса.
- `src/style.css`, `src/business.css` — стили обеих сторон.
- `tests/domain.test.js` — подтверждение рейтинга, некорректные AI-ответы, права на решения и однократное начисление баллов.

Хранение: `alem.workspace.v2` (задачи, команды, предложения, закладки и бизнес), `alem.editor.v2` (текущая форма) и `alem.role` в localStorage. Старые профиль, закладки и предложения из первой версии импортируются при создании нового хранилища.

Основные модели:

- Task: `id`, `ownerId`, `title`, `description`, `context`, `users`, `data`, `result`, `success`, `constraints`, `contact`, `interaction`, `category`, `weeks`, `published`, `confirmed`, `score`.
- Proposal: `id`, `taskId`, `teamId`, `idea`, `plan`, `deadline`, `link`, `status` (`pending`, `selected`, `rejected`), `createdAt`.
- Milestone внутри Proposal: `description`, `link`, `status` (`submitted`, `confirmed`), даты отправки/подтверждения.

Сервер, авторизация и синхронизация между браузерами не подключены. Переключение ролей — только демонстрационная функция. Для интеграции заменить операции хранилища API-вызовами; на сервере проверять владельца задачи, выбранную команду, переходы статусов и однократность подтверждения этапа. Рейтинг также должен пересчитываться сервером. В демо доступен один этап на предложение. Картинки и иконки не требуют внешних API; шрифт загружается с Google Fonts с системным запасным вариантом.
